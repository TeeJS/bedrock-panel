# Bedrock Panel v0.9.9-beta.3 — Windows beta: the chosen mic, really

This beta fixes why beta.2 still listened on the Windows default microphone. It is a **beta for
testers** on Windows; macOS and Linux stay on v0.9.8.

## What changed since beta.2

### The mic you chose is the mic that opens

Beta.2 found the right microphone by name but then asked the browser engine for it as a
preference rather than a requirement, and the engine opened the Windows default instead. So a mic
chosen in Bedrock Panel only ever worked while it was also the Windows default. Every place that
opens a microphone now asks for the chosen device outright:

- **LucidType** dictation
- **AI Voice** and **Live Translate**
- The **meeting recorder**
- The **Test microphone** button under **Settings → General → Audio**

If the chosen mic can't be opened, because it is unplugged, Bedrock Panel still falls back to the
Windows default so nothing stops working, and LucidType's header now says which mic it couldn't
open and which one it is using instead.

Everything from beta.1 and beta.2 is still here: fewer phantom turns in AI Voice, LucidType saying
why no text appears, Open WebUI tools that run instead of being read aloud, the Claude Code sign-in
hint, and web pages that use Bedrock Panel's mic.

**Download:** `bedrock-panel-setup.exe` (installer) or `bedrock-panel-portable.exe`. Like the earlier
betas, this one is not offered as an automatic update; install it by hand.

## What to try

- Set Windows' default mic to a different device than the one in **Settings → General → Audio**.
  Dictate in **LucidType**: the text should appear, and main.log should say `capturing from
  "Microphone (…)"` naming your chosen mic, without the "Default -" prefix.
- Unplug the chosen mic and start dictation again: the header should name the mic it couldn't
  open and say it is using the Windows default.
- **AI Voice** and the **meeting recorder** with the same setup: both should pick up the chosen mic.
