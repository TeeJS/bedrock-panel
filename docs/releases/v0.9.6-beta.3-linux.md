# Bedrock Panel v0.9.6-beta.3 — Linux beta (x64)

Bedrock Panel runs on Linux with the DK-QUAKE: Software mode, Panel mode on the 1920×480 display,
the knob and touchscreen, the tile grids, the editor, dashboards, and every platform-neutral app.
This is a **beta for testers**. Everything below is verified on Ubuntu 26.04 with KDE Plasma 6.6 on
Wayland, PipeWire, and a real DK-QUAKE.

## What changed since beta.2

**Input.** beta.2 could not press a key or move a pointer. This build does all three of the things
that were listed as the next milestone.

- **Macros, media keys, and typed text** work. Bedrock Panel creates a virtual keyboard through
  `/dev/uinput`, which the kernel presents as ordinary hardware, so the compositor routes its
  keystrokes like any other keyboard — the same on X11 and Wayland, with nothing to approve.
- **Global hotkeys** work, with one consent step the other platforms do not have. See below.
- **Monitor mode** works. The panel hides, the display becomes an ordinary strip of desktop, touch
  drives the cursor and the knob scrolls. It was unavailable in beta.2 because the pointer half did
  not exist.

Nothing else changed. The starter grid, packaging, and display handling are beta.2's.

**Download:** `bedrock-panel_amd64.deb` for Debian and Ubuntu, or `bedrock-panel-x86_64.AppImage`
for anything else. Windows and macOS builds are unchanged in this beta (v0.9.5 remains current).

## First launch

The whole walkthrough is in **docs/linux.md**. In short:

1. `sudo apt install ./bedrock-panel_amd64.deb`. **Device access is set up for you** — the package
   installs the udev rule the console and the virtual keyboard need, because `apt` already runs as
   root. Plug the QUAKE in and it is detected.
2. Running the **AppImage** or from source instead? There is no installer, so the rule is one
   command: the editor's **Settings → Hardware → Device access** shows whether it is active and
   prints the exact command for your install, with a Copy button.
3. **Set the panel display to landscape** so the desktop sees 1920×480 rather than 480×1920. On KDE
   that is `kscreen-doctor output.DP-1.rotation.right`, or Display Configuration in System Settings.
   Either orientation is detected, but only landscape lines the pointer up with what you see.
4. Nothing else. There are no permission prompts to grant on Linux.

**Packages are unsigned.** Linux has no equivalent gatekeeper, so nothing asks you to allow the app.

## What to try

- **Macros and media keys** — any tile that sends a key combo, types text, or drives playback. Combos
  like Ctrl+C are layout-independent. Typed text assumes a US QWERTY layout, because a virtual
  keyboard sends key *codes* and your layout decides what they print; a character with no key on your
  layout is skipped with a line in the log rather than failing the whole macro.
- **Global hotkeys** — set one in the editor under **Settings → Global shortcuts**, or a page's
  **Jump-to-page shortcut**. The first time they are registered, KDE puts up a **Global Shortcuts
  Requested** dialog listing each one with the key you chose already filled in. Click **OK** and they
  are live. This is Wayland's design and not a Bedrock Panel limitation: no application may take a key
  combination for itself, so it asks the desktop and the desktop asks you. Chromium's own hotkey
  support goes through the same portal and needs the same consent.
- **Monitor mode** — the tray icon, or the editor's **Settings → Monitor mode**. The tile grid hides
  and the QUAKE becomes a plain second screen you can drag a window onto. Tap to click, drag to move
  with the button held, turn the knob to scroll, press it for Enter. Both knob actions are
  configurable in that settings block. Leave the mode from the tray, which is why the knob is free.
- **Panel mode on the Quake** — the panel covers the 1920×480 display. In a Wayland session the app
  restarts itself once at launch to run through XWayland, and logs one line saying so: a native
  Wayland client is not allowed to place a window on a chosen screen, and Panel mode is nothing but
  placement. `BEDROCK_LINUX_OZONE=wayland` skips the restart, at the cost of Panel mode.
- **Starter pages** — a fresh install starts with Linux pages whose tiles name the *job*, so they
  launch whichever program your machine has. An existing config: editor → **+ Add page → Starter
  pages…**.
- **A config copied from Windows or a Mac** — program names are mapped to their Linux equivalents
  and `start <url>` becomes `xdg-open`, so the pages you already built keep working.
- **Secrets** — saved passwords and tokens go to KWallet or GNOME Keyring.
- **Device Diagnostics** — names Linux, and says when a device open was refused for want of the
  udev rule rather than blaming a cable.

## Known limits in this beta

- **If you dismiss the global shortcuts dialog, the hotkeys register with no key.** Nothing breaks
  and nothing fires. Restart Bedrock Panel to be asked again, or give them keys in System Settings →
  Shortcuts under Bedrock Panel. The editor shows what the desktop actually granted, so an unbound
  hotkey is visible rather than silently dead.
- **Macros stopping after a while is a permissions problem, not a bug in the macro.** `/dev/uinput`
  is handed to whoever is logged in, and that grant is applied when a device is *added* to your
  session — which a boot-time device can miss. The dependable fix is group membership:
  `sudo usermod -aG input $USER`, then log out and back in. The log names this when it happens.
- **A display scaled to anything other than 100% is untested** with Monitor mode. The cursor mapping
  works in logical pixels and should be unaffected, but nobody has measured it. If your cursor lands
  somewhere other than your finger, say what your scaling and arrangement are.
- **Reserved Display** and **follow the focused app** are not available. Both need to enumerate and
  move other applications' windows, which Wayland does not allow.
- **Teams window control** cannot work for the tiles that focus the Teams window first. Zoom is
  unaffected, because its shortcuts need no focus.
- **Now playing, system volume, and call detection** are not wired up yet, so the Music page is
  blank, the meeting console's output rail shows a dash, and auto-record does not start on its own.
  Manual recording works, and the media *keys* do work — it is reading the state back that is missing.
- **Outlook desktop meeting info** is Windows-only; use the Microsoft 365 source, which works
  everywhere.
- **Built-in speech** is Windows and macOS only. Point the voice apps at a Wyoming server such as
  faster-whisper or piper; the app already speaks that protocol.
- **The touchscreen wizard** does not exist and is not needed: it fixes a Windows-only problem.
- **A GPU process crash** was seen during development on Intel graphics with Mesa 26 and has not
  recurred in many launches since. The OEM DK-Suite build showed the same crash on the same machine,
  which points at the graphics stack. If you see `bedrock-panel` core dumps in `coredumpctl list`,
  please report it with your Mesa version (`glxinfo -B | grep Mesa`).
- **AppImage needs FUSE 2**, which Ubuntu 24.04 and newer no longer ship. Install `libfuse2t64` or
  use the `.deb`.
- x64 only. No arm64 build yet.
