For Google Drive link sources: reads the folder straight from Google's servers, so it sees everything shared with you — the local Drive mount can hide other members' files — and needs no Drive for Desktop. Requires the Google Drive connection (set it up from the chip on the main screen). Content compare uses Google's checksums without downloading.

Drive-API jobs only: converts Google-native documents as they copy — a Sheet becomes .xlsx, a Doc .docx, a Slides deck .pptx (named after the document). Off, they're skipped (they have no downloadable file). Google caps document export at 10 MB — larger ones report an error. Exported files are compared by modification time only (Drive gives no size or checksum for them).

You can paste a Google Drive folder link — it resolves to your Drive for Desktop mount at run time (the folder needs a shortcut in your Drive: right-click → Organize → Add shortcut). Paths may contain date tokens that expand when the job runs — D:\Backup\<yyyy-mm-dd> becomes D:\Backup\2026-08-30. Tokens: yyyy yy mm dd hh nn ss day month dow doy woy wom quarter.

Follow shortcuts copies what a .lnk points at — a Google Drive folder shortcut becomes a real folder (named like the shortcut) with the target's content — instead of copying the useless .lnk file itself.

Match source timestamps & read-only stamps each copied file and folder with the source's modified/access time and its read-only attribute (folder times are applied after copying, so they stick). Creation time can't be set from here on Windows, so it stays the copy date. Local folder jobs only.

Writing a rule

    A rule teaches FileBridge how one subscription site is laid out and how a download is triggered.
  

  

    
    
A job is a listing URL you paste plus a destination folder. A rule (this file) is matched to the job by hostname and tells FileBridge how to walk the site. Rules are yours — they live in your config folder, one <site>.json per site. Editing here validates on Save; you can also Open rules folder and edit the files in any text editor.


    
Start here — four questions

    
    
      
  1. How do you sign in? Note the login page URL, and one element that only shows when signed in (an account link, avatar) — that becomes auth.probeSel. Note any URL fragment the site shows when signed out (e.g. /login) → auth.loggedOutUrlIncludes.
    2. 
      
  2. How are collections listed? A page listing many collections (a vault/library) → listing mode; find the substring shared by every collection link (e.g. /projects/) → collectionHrefIncludes. A numbered series (drop-360, drop-359…) → sequential mode with a pattern like /drops/drop-{n}.
    3. 
      
  3. One level or two? A collection page listing several downloadable items → collection.itemSel (a selector for those item links). Each collection page is the single download → collection.selfItem: true.
    4. 
      
  4. What triggers the download? See Download triggers below.
    5. 
    


    
The rule file

    
{
  "site": "example",                 // short lowercase id; also the filename
  "name": "Example Site",            // label shown on the session chip
  "match": ["example.com"],          // hostname(s); www.example.com is covered too
  "auth": {
    "loginUrl": "https://www.example.com/login",
    "probeSel": "a[href*='/account']",     // present ONLY when signed in
    "loggedOutUrlIncludes": ["/login"]     // a run seeing this stops: "sign in"
  },
  "sources": [
    { "id": "releases", "mode": "listing",
      "collectionHrefIncludes": "/release/",  // listing mode
      "listUrl": "/releases" }                // optional; defaults to the job's URL
    // sequential instead:  "mode": "sequential", "pattern": "/drops/drop-{n}"
  ],
  "collection": { "itemSel": "a[href*='/item/']" },
  //  or:         { "selfItem": true }        // the collection page IS the item
  "item": {
    "nameSel": "h1",                          // selector for the item's title
    "downloadClickText": "download",          // visible text of the download control
    "downloadAllSel": null,                   // optional: a chooser's file rows
    "downloadTimeoutMs": 180000               // wait for the download to start (def 10 min)
  },
  "delayMs": 4000,                            // polite pause between items (min 500)
  "pathPattern": "{collection}\\{item}"       // tokens: {site}{collection}{item}{yyyy}{mm}{dd}
}


    
Download triggers

    
    
      
  • One button: "downloadClickText": "download" — its visible text. Icon-only buttons with a separate text label work too; FileBridge clicks the real control next to the text.
    • 
      
  • Menu, then button: a list clicked in order — ["download files", "download"].
    • 
      
  • A chooser of several files (STL / renders / media, labels varying per product): set downloadAllSel to a selector for the chooser's rows — FileBridge clicks the control in every visible row. With it set, downloadClickText is used only to open the chooser.
    • 
    


    
Gotchas worth knowing

    
    
      
  • Membership-gated pages may render links only after a check (e.g. Patreon). FileBridge waits up to 20 s; make sure your selectors match the rendered page while signed in.
    • 
      
  • An empty listing is an error, not "nothing new" — so a wrong selector or a dead session fails loudly instead of silently syncing nothing.
    • 
      
  • A trigger that navigates off the item page breaks the download — keep downloadClickText on the item page.
    • 
      
  • Slow prep is fine. Sites that take minutes to build a file are handled; raise downloadTimeoutMs for very slow ones.
    • 
      
  • Sign in inside FileBridge once per site via the session chip's Open sign-in window — being logged in elsewhere isn't enough.
    • 
    


    
Test it

    
    
      
  1. Save the rule (here, or drop the .json in the rules folder).
    2. 
      
  2. Add a Web drops job: the site's listing URL as source, a scratch destination, Per run = 1.
    3. 
      
  3. Sign in via the site's session chip, then Run — expect one collection's files under dest\{collection}\{item}\.
    4. 
      
  4. Run again → 0 downloaded, N already seen proves the ledger works. If it errors "no collections found", recheck the probe and the listing selector.
    5. 
    


    
Two starting points

    
Listing, single-level (each listed page is the item, one Download button):

    
{
  "site": "myvault", "name": "My Vault", "match": ["myvault.example"],
  "auth": { "loginUrl": "https://myvault.example/login",
            "probeSel": "a[href*='/profile']", "loggedOutUrlIncludes": ["/login"] },
  "sources": [{ "id": "vault", "mode": "listing",
                "collectionHrefIncludes": "/projects/", "listUrl": "/projects" }],
  "collection": { "selfItem": true },
  "item": { "nameSel": "h1", "downloadClickText": "download model files",
            "downloadTimeoutMs": 300000 },
  "pathPattern": "{item}"
}

    
Sequential, two-level with a file chooser (numbered drops, several files each):

    
{
  "site": "mydrops", "name": "My Drops", "match": ["drops.example"],
  "auth": { "loginUrl": "https://drops.example/login",
            "probeSel": "a[href*='/account']", "loggedOutUrlIncludes": ["/login"] },
  "sources": [{ "id": "main", "mode": "sequential",
                "pattern": "/drops/drop-{n}", "listUrl": "/drops" }],
  "collection": { "itemSel": "a[href*='/product/']" },
  "item": { "downloadClickText": "download files",
            "downloadAllSel": "[class*=FileRow]", "downloadTimeoutMs": 600000 },
  "delayMs": 4000, "pathPattern": "{collection}\\{item}"
}
